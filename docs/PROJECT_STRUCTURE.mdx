# Как устроен проект

Это исходники npm-библиотеки `@microfronts/ui`. Здесь нет запуска приложения, маршрутизации и бизнес-логики. Storybook служит средой просмотра и проверки компонентов; потребитель устанавливает собранный пакет и подключает его CSS.

## Карта файлов

Пути в таблицах указаны относительно корня репозитория.

## Почему useFormField вызывает useController, а не рисует Controller

Контроллер здесь уже есть: `useFormField` вызывает `useController` из React Hook Form. Этот хук отдаёт значение, обработчики, ref и состояние поля. Компонент `Controller` той же библиотеки построен поверх `useController` и вызывает переданную render-функцию. Это два интерфейса одного механизма. См. [исходник Controller](https://github.com/react-hook-form/react-hook-form/blob/master/src/controller.tsx).

Наш хук добавляет к связи RHF идентификатор через useId, идентификаторы описания/ошибки и строку describedBy. Input использует их в htmlFor, id и aria-describedby. Разделение позволяет переиспользовать эту логику в будущих полях, не вынося JSX конкретного Input в общий слой.

Поток данных такой: useForm создаёт control → Input передаёт его и name в useFormField → useController связывает поле с формой → Input передаёт field примитиву. При вводе вызывается field.onChange, при потере фокуса — field.onBlur. Ошибка приходит через fieldState; ref позволяет RHF сфокусировать ошибочное поле. Control можно передать явно или получить из FormProvider.

| Подход                           | Когда подходит                                                        | Компромисс здесь                                                                                                      |
| -------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| useController в собственном хуке | Переиспользуемые поля библиотеки с общей логикой доступности          | Выбран для разделения данных и разметки. Не обещает отсутствия ререндеров.                                            |
| Controller с render              | Подключение стороннего контрола непосредственно в форме               | Также корректен; при повторении полей нужно отдельно вынести общие ARIA-связи.                                        |
| register                         | Простой нативный input, для которого подходит неконтролируемый подход | Может быть проще. Сложным контролам с нестандартными событиями нужен адаптер.                                         |
| Собственный useState             | Поле вне RHF или локальное состояние UI                               | Не стоит дублировать в нём значение, уже управляемое RHF: пришлось бы синхронизировать reset, ошибки и dirty/touched. |

Для будущего Checkbox потребуется отобразить field.value в checked, а изменение — в boolean. Сам useFormField этого не делает: он общий слой связи, а не готовая универсальная обёртка для любых элементов.

Zod используется на уровне useForm через resolver в примере. Input отображает результат валидации и не выбирает бизнес-правила. Схема email из истории не встроена в публикуемый компонент.

## Стили компонентов и подключение пакета

Button и Input задают дополнительные стили Tailwind-классами в своих обёртках: границы, active, hover, focus-visible и aria-invalid. Исходники примитивов не меняются. Input использует Field, FieldLabel, FieldDescription и FieldError из shadcn; useFormField сохраняет связь с RHF и ARIA-идентификаторы.

Сборка tsup добавляет статический CSS-импорт в ESM/CommonJS. Сборщик приложения подключает готовый CSS без ручного импорта styles.css. Подпуть CSS сохранён. Для исполнения в чистом Node нужен CSS loader; SSR через сборщик должен обрабатывать CSS. Проверка пакета отдельно проверяет извлечение CSS сборщиком и экспорты Node с тестовым CSS loader.
Тема задаёт CSS-переменные, а .dark на предке переключает их значения. Storybook использует общую CSS-основу и тот же плагин относительных единиц, что и сборка пакета; источники классов документации подключает отдельно. Сборщик переводит px из генерируемых правил в rem, поскольку сами примитивы менять нельзя. Расчёт px/16 предполагает базу 16 CSS px; при другом корневом размере rem масштабируется.

В CSS входит Tailwind Preflight и базовые правила body/\*: они действуют на страницу потребителя. Это осознанное ограничение текущей поставки, а не полная изоляция стилей компонентов.

## Как пользоваться ESLint и Prettier

```sh
npm run lint
npm run lint:fix
npm run format
npm run format:check
```

lint и format:check ничего не переписывают и возвращают ошибку при нарушениях. lint:fix применяет доступные исправления ESLint; format переписывает форматирование поддерживаемых файлов. Для полного цикла перед завершением задачи затем выполняются typecheck, test, check-package и build-storybook.

ESLint проверяет код, включая тесты и конфигурации, но не CSS/Markdown. Настройки TypeScript здесь не используют информацию о типах из проекта: за проверку типов отдельно отвечает tsc. Включены rules-of-hooks и exhaustive-deps; правила React Compiler не подключаются, поскольку компилятор в проекте не настроен.

Prettier форматирует также CSS, JSON, Markdown и MDX. eslint-config-prettier последним отключает конфликтующие форматирующие правила ESLint; Prettier не запускается внутри линтера. Такое разделение соответствует [рекомендации Prettier](https://prettier.io/docs/integrating-with-linters). Структура ESLint основана на [flat config](https://eslint.org/docs/latest/use/configure/configuration-files) и [typescript-eslint](https://typescript-eslint.io/getting-started/).

Неизменяемые примитивы исключены из обоих инструментов. Их поведение остаётся охвачено браузерными тестами через публичные компоненты.

Автоформатирование при сохранении редактора и Git hooks не устанавливаются: команды работают независимо от выбранного редактора.

## Дополнения к историям и сборке

- `src/components/Badge/Badge.stories.tsx` и `src/components/Panel/Panel.stories.tsx` документируют остальные публичные компоненты, включая варианты Badge и вложенное содержимое Panel.
- `src/components/Button/Button.test.tsx и src/components/Input/Input.test.tsx` проверяет реальный клик/клавиатуру Button, disabled, ввод/валидацию/сброс Input через Playwright.

- [BUILD.mdx](BUILD.mdx) объясняет пайплайн сборки, текущие размеры и возможности оптимизации.

## Совместное размещение

```text
src/
  components/
    Button/
      Button.tsx
      Button.stories.tsx
      Button.test.tsx
    Input/  # Input.tsx, Input.stories.tsx, Input.test.tsx
    Badge/  # Badge.tsx, Badge.stories.tsx, Badge.test.tsx
    Panel/  # Panel.tsx, Panel.stories.tsx, Panel.test.tsx
  form/
    use-form-field.ts
    use-form-field.test.tsx
    README.md
  test/
    render.tsx
  docs/
    Introduction.mdx
```

src/test/render.tsx создаёт React root и очищает его после теста; общая утилита не входит в сборку библиотеки. Тесты хука в src/form/use-form-field.test.tsx проверяют его контракт независимо от примитива Input. [Руководство формы](../src/form/README.md) содержит практические примеры.

Перемещение файлов не меняет npm API: потребитель продолжает импортировать из @microfronts/ui и подпутей /button, /input. Входы tsup перечислены явно, поэтому соседние истории/тесты в JS-пакет не включаются. Tailwind сканирует папку компонентов, исключая истории, unit-тесты и Playwright-сценарии.

## Состояния и тестирование Storybook

`.storybook/story-states.mjs` — Vite/PostCSS-плагин только для документации. После генерации Tailwind он добавляет варианты селекторов hover/focus-visible для атрибута data-story-state на декораторе. Декларации стилей не дублируются вручную; runtime-addon Pseudo States удалён. После изменения Vite-конфигурации нужен полный перезапуск Storybook.

`Input.stories.tsx` показывает поле без кнопок и использует реальный Input как meta.component. `Input.form.stories.tsx` показывает отдельно интерактивную форму с Zod и результатом отправки. `src/docs/Testing.mdx` описывает проверки непосредственно в Storybook.

`playwright.config.ts` запускает тесты `*.stories.spec.ts` рядом с компонентами. Они проверяют реальные страницы Canvas/Docs и содержат test.step с описаниями. `src/test/storybook.ts` открывает нужную историю/тему и отключает переходы цвета только для стабильного сравнения CSS. Результаты — playwright-report и test-results, исключённые из Git и форматирования.

### Инструкции для агентов

`AGENTS.md` содержит постоянные границы библиотеки: её назначение, неизменяемость shadcn-примитивов, размещение кода и совместимость публичного API. Подробные повторяемые workflows хранятся как versioned project skills в `.agents/skills/`:

| Путь                                                     | Когда применять                                                                       |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `.agents/skills/ui-library-development/SKILL.md`         | Изменение публичного компонента, формы или истории Storybook.                         |
| `.agents/skills/ui-library-verification/SKILL.md`        | Выбор и фиксация проверок после изменения библиотеки.                                 |
| `.agents/skills/ui-library-package-maintenance/SKILL.md` | Изменение exports, зависимостей, tsup, CSS-поставки, package metadata или Changesets. |

В `.agents/skills/` могут находиться локально установленные skills, например `shadcn`; они исключены из Git. Три workflows выше явно включены правилами `.gitignore`, поэтому становятся частью репозитория и одинаково доступны его участникам.

## Локальные артефакты

Планы в `.codex/plans/` остаются на диске и исключены из Git. `.vitest-attachments/` и `src/**/__screenshots__/` содержат диагностические результаты текущих тестов, а не эталоны сравнения изображений; они также исключены. Если появятся визуальные snapshot-тесты, их эталоны нужно хранить отдельно и включать в Git.

## Разделение CSS и проверка сборки

- `src/styles.base.css` подключает Tailwind, tw-animate-css, служебный CSS shadcn, неизменяемую тему и классы примитивов.
- `src/styles.css` добавляет классы публичных компонентов, исключая stories/test/spec. Этот вход используется сборкой npm и тестами компонентов.
- `.storybook/styles.css` добавляет классы историй, MDX и preview; его импортирует preview.tsx. Глобальные стили и токены не дублируются вручную.
- `scripts/finalize-build.mjs` вызывается tsup после успешной сборки, включая watch, и устраняет повторные хвостовые ссылки на одну sourcemap, которые создаёт tsup 8.5. Код и карта не меняются.
- `scripts/check-package.mjs` дополнительно проверяет отсутствие стилей декоратора и псевдосостояний Storybook в CSS пакета, единственность ссылок на sourcemaps и удаление RHF при импорте одного Button из корня.

Пути руководств: `docs/BUILD.mdx` и `docs/PROJECT_STRUCTURE.mdx`. Они служат документацией репозитория; страницы в интерфейсе Storybook находятся в `src/docs/*.mdx`.

### Языковой режим CSS в VS Code

`.vscode/settings.json` назначает режим `tailwindcss` трём CSS-входам: `src/styles.base.css`, `src/styles.css` и `.storybook/styles.css`. Его предоставляет Tailwind CSS IntelliSense (`bradlc.vscode-tailwindcss`). Это позволяет редактору распознавать `source(none)` и `@source`; обычная CSS-валидация остальных файлов не отключается. Настройка применяется, когда пакет открыт как папка рабочего пространства VS Code.
